# AGENTS.md

Texas Hold'em poker **library** (no app or binary). Module `hands`, `go 1.20` (no `slices`/`maps` packages, no builtin `min`/`max`). Single dependency: `gonum.org/v1/gonum` (used only for combinations).

## Commands

- The shell exports a stale `GOROOT` (`go1.22.9` while the `go` binary is newer), so plain `go build` fails with "version does not match go tool version". ALWAYS run Go as `env -u GOROOT go ...`. The `Makefile` already handles this via `GO ?= env -u GOROOT go`; CI does not need the workaround because `GOROOT` is unset there.
- Local checks go through `make`: `make build`, `make vet`, `make fmt`, `make test` (with `-race`), `make test-short`, `make lint` (requires `golangci-lint` locally), and `make check` (`fmt build vet test`).
- Tests exist for every package (card, deck, hand, player, pot, table, helpers, tournament). `-short` skips the exhaustive C(52,5) hand-category enumeration in `src/engine`; the full `-race` run takes ~17s for that package.
- First build needs `go mod download` (fetches gonum); offline environments fail here.
- CI lives in `.github/workflows/ci.yml` and runs gofmt, build, vet, tests on Go `1.20.x` and `stable`, plus non-blocking `golangci-lint` (config in `.golangci.yml`). Only the first four checks must pass before merge; lint findings are advisory.

## Layout

- `src/engine` — all domain code: `Card`/`Suit`, `Hand` (ranking + comparisons, single evaluator in `hand_eval.go`), `Deck`, `Table` (betting state machine in `betting.go`, side pots in `sidepots.go`, rules in `rules.go`, ante posting and blind position in `antes.go`, mid-tournament `SetRules` in `rules.go`), `Player`, `Pot`, legacy `Bet`, `IdMaker`.
- `src/tournament` — single-table SNG on top of `engine`: blind levels by completed hands, entry lifecycle (late registration, re-entry, add-ons, fixed bounties, sit-out), registration/start, places, payouts, standings and winner detection.
- `src/helpers` — combinations (gonum), random IDs (`crypto/rand`), random ints.
- Imports use `hands/src/...`, not a VCS path. No root package, no `internal/`.
- `cmd/` is gitignored (`cmd`, `cmd/*`). `cmd/test/main.go` is an untracked local scratch playground — not an entrypoint, don't put real code there.

## API facts

- Card strings are value+suit with no separator: `"10H"`, `"2C"`, `"AS"`. Suits are H/D/S/C only (`Clubs`).
- Parsing is strict: `ParseCard(s) (*Card, error)` validates and uppercases; `NewCardFromString` is deprecated and PANICS on invalid input. `NewHandFromStrings`/`NewHandFromCards` return `(*Hand, error)`.
- Suits: type `Suit`, `CardSuit`, `SuitColor`, `Suits`, `SuitsNum`, field `Card.Suit` (a `*CardSuit`; access the suit itself as `c.Suit.Suit`). `Clubs` is current; `Crosses` is a deprecated alias. `Suite`-named identifiers remain only as deprecated wrappers (`SuiteFromString`, `CompareSuites`).
- `Hand` stores a sorted `[]*Card` (exactly 5 cards). `Hand.Define()` returns the category; `Hand.Compare` ranks two hands (total order incl. kickers, wheel A-2-3-4-5, wheel straight flush, royal flush). `Hand.CountPairs` returns the number of pairs (0..2), not paired cards.
- `NewDeck()` starts empty. `NewDeckWithRand(*rand.Rand)` enables deterministic tests; `Deck.Shuffle()` resets to 52 unique cards and shuffles; `Deck.Len()` exists. `StartHand` shuffles afresh every hand.
- Betting flow: `NewTableWithRules(...)` (or the legacy `NewTable`) → `StartHand()` → `Act(...)` until the street completes → `NextStreet()` → repeat → `Showdown()`. `StartHand` resets state, sits out empty stacks and players with an active sit-out, moves the dealer, posts antes and blinds, deals pockets and opens preflop betting. `Act` enforces turn order, min raises, short all-ins and the raise cap.
- `Action{PlayerID, Type, Amount}`. `Amount` for `bet`/`raise` is the player's total street commitment ("raise to"). There is no explicit all-in action: using the rest of the stack makes the action all-in. `LegalActions` returns the available types; `ToCall` returns the missing amount.
- `Street`: `preflop`, `flop`, `turn`, `river`, `showdown`. `HandPhase`: `waiting`, `betting`, `street-complete`, `showdown`, `complete`. `NextStreet` only runs in `street-complete`; after the river it moves to `showdown`. If every remaining player is all-in, `NextStreet` runs the board out automatically.
- `TableRules` (in `rules.go`) has `MinPlayers`, `SmallBlind`, `BigBlind`, `Ante`, `AnteMode`, `MinRaise` (0 → big blind), `MaxRaisesPerStreet` (0 → unlimited; counts all aggressive actions) and `OddChipRule` (`OddChipLeftOfDealer`). `Ante == 0` disables antes. `AnteMode` has `AntePerPlayer` (`"per-player"`, default when empty) and `AnteBigBlind` (`"big-blind"`). Only no-limit Hold'em is implemented.
- `Table.SetRules` replaces the normalized rules only in `PhaseWaiting` or `PhaseComplete`; it does not touch the current hand or pot. Use it between hands, e.g. when a tournament advances a blind level.
- Antes (`src/engine/antes.go`): `StartHand` and the deprecated `Blinds()` helper post antes before the blinds. Per-player mode posts from every active player; big-blind mode posts only from the big blind. Antes are dead money: they go into the pot but not into `streetBet`, `currentBet`, `ToCall`, minimum raise or raise-cap calculations. A short stack posts `min(ante, stack)`, becomes all-in, stays active, gets pocket cards, cannot act and can only win pots it is eligible for. `Table.Ante() Chips` returns the configured ante.
- Side pots: `Showdown` builds layers from total contributions, refunds unmatched chips, excludes folded players, evaluates each layer's eligible players, splits ties and assigns odd chips left of the dealer. `ResolvePots` is the read-only preview; `LastResults` returns the last payouts. `ResolveWinner` is deprecated legacy behavior.
- Tournament API (`src/tournament`): `NewTournament(name, tag, idMaker, *TournamentRules)`, `Register(name)`, `Start()`, `StartHand()`, `Act`, `NextStreet()`, `Showdown()`, `Reenter(previousPlayerID)`, `AddOn(playerID)`, `SitOut(playerID)`, `SitIn(playerID)`, `Standings()`, `State()`, `Level()`, `HandsInLevel()`, `HandsPlayed()`, `Rules()`, `PrizePool()`, `EntryCost()`, `AddOnCost()`, `FeesCollected()`, `BountyPool()`, `BountiesPaid()` and read-only `Table()`. `TournamentRules` has `StartingStack`, `MinPlayers` (0 → 2), `MaxPlayers` (0 → 9), `Levels`, `Payouts`, `BuyIn`, `Fee`, `Guarantee`, `PayoutMode`, `PercentPayouts`, `LateRegUntilLevel`, `ReentryAllowed`, `MaxReentries`, `AddOnAfterLevel`, `AddOnBuyIn`, `AddOnFee`, `AddOnChips` and `Bounty`. All new fields are additive; zero values keep the original freezeout SNG behavior. `BlindLevel.Hands` counts completed hands; the last level repeats forever. `PayoutMode` is `PayoutModeFixed` (empty normalizes to it), `PayoutModePercent` or `PayoutModeWinnerTakeAll`. Fixed and percent places must be contiguous from 1, fit within `MaxPlayers`, and `Start` requires no more places than entries; percent values must sum to exactly 100. Only the payout table for the selected mode may be set. Payout amounts are abstract `int` prize units, not chips.
- Entry lifecycle (`src/tournament`): `LateRegUntilLevel` is a 1-based, inclusive level count (0 disables); `Level()` itself stays 0-based. `Register` works in `StateRunning` only inside that window and seats into a free or busted seat, failing when the table has no seat; late entries and re-entries shift already-eliminated places down so final places stay unique. `Reenter` requires a busted entry, `ReentryAllowed`, and an open late-registration window; it returns a new player/entry with a fresh stack and the old display name, while the old entry keeps its own ID and standing row. Only one entry in a re-entry chain may be active at a time, so the current entry must bust before another re-entry. `MaxReentries` caps re-entries per chain (0 → unlimited), counted on the chain root. `MaxPlayers` is a concurrent seat limit, not a total entry limit. `AddOnAfterLevel` is 1-based (0 disables); the one-add-on-per-entry window is between the level-completing showdown and the next hand, and the level must have a following level. `AddOn` adds `AddOnChips`. `SitOut`/`SitIn` are between-hand operations; sitting out keeps chips but skips cards, blinds, antes and the button, and sitting in requires a positive stack. `Standing` exposes `PlayerID`, `Name`, `Chips`, `Place`, `Prize`, `Eliminated`, `BountyWon` and `SittingOut`.
- Tournament accounting: `PrizePool()` is `max(BuyIn * entries + AddOnBuyIn * add-ons, Guarantee)`, grows with entries, late registrations, re-entries and add-ons, and fees and bounties are excluded. `EntryCost()` is `BuyIn + Fee + Bounty`; `AddOnCost()` is `AddOnBuyIn + AddOnFee`; `FeesCollected()` is `Fee * entries + AddOnFee * add-ons`; `BountyPool()` is `Bounty * entries`. Entries include late registrations and re-entries. Percent and winner-take-all modes require a positive starting pool (`BuyIn > 0 || Guarantee > 0`). In fixed mode without a `BuyIn`, `Guarantee` or `AddOnBuyIn`, payouts stay abstract legacy units and the pool is zero; with accounting enabled, `Start` rejects a payout total above the pool. Percent prizes are floored with leftover units assigned by largest remainder, ties favouring the better place (lower place number).
- Bounties: `Bounty` is a fixed amount per entry, included in `EntryCost` but never in `PrizePool`. A busted entry's bounty is paid immediately to the winners of the pot layer that eliminated it (the largest non-refunded layer it was eligible for); split pots divide the bounty evenly with the remainder clockwise from the dealer. Unclaimed bounties and the survivor's own bounty are awarded at the finish. `BountiesPaid()` includes those final awards; `Standing.BountyWon` is per entry.
- Tournament elimination: a busted player's place is based on the stack at the start of the hand; larger stacks get better places, equal stacks share a place and consume the following places. Payout places consumed by a tie are split evenly, with remainders clockwise from the dealer. Prizes are awarded when the tournament finishes.
- `Table.Blinds`, `PreFlop`, `Flop`, `Turn`, `River`, and `Player.Check/Call/Raise/Fall` are deprecated low-level helpers that bypass the state machine. `Player.ResetForHand()` activates only funded players that are not sitting out; folded players keep their cards for history.
- Table lifecycle (`src/engine/lifecycle.go`): `SeatPlayer` seats a new player in a free seat or the first busted seat, erroring when every seat holds a funded player. `ReplacePlayer(oldID, player)` swaps a busted player into the same seat (button stays valid) and requires the old player to have 0 chips. `AddChips` adds a positive amount between hands. `SitOut`/`SitIn` work only between hands; a sitting-out player is inactive, gets no cards, posts no blinds/antes and holds no button, and `SitIn` requires a positive stack. `Player.IsSittingOut()` exposes the flag. These operations require `PhaseWaiting` or `PhaseComplete`.
- `Table.ResolveWinner()` requires exactly 5 board cards, evaluates only active players, returns ALL tied winner IDs sorted alphabetically, and never panics. `GetFirstPosition`, `GetSecondPosition`, `GetDealer` return `(*Player, error)`. `Table.GetPlayersHand` still requires exactly 7 cards (5 board + 2 pocket).
- `Player` uses an unexported mutex, returns copies of pocket cards, validates bets and never goes negative. `Pot.Register` registers new players and errors on duplicates; `Pot.Reset` zeroes the total; negative bets are rejected. `Pot.RemoveChips` backs refunds/payouts.
- Comments and error messages mix Russian and English. Match the surrounding language instead of translating.

## Known limitations

- No-limit Hold'em only; fixed-limit and pot-limit are not implemented.
- Tournament support is single-table SNG only. Late registration is limited to the configured `LateRegUntilLevel` window, and re-entry requires that window to remain open. Still out of scope are MTT (including MTT re-entry), progressive/knockout bounties (only a fixed per-entry bounty), hand-for-hand play, ICM/deal-making and persisted hand history. `Payout.Amount`, `BuyIn`, `Fee`, `Bounty` and `PrizePool()` are abstract prize units, not chips.
- No straddles.
- Hand history/action log is not persisted; `LastResults` only keeps the latest payouts.
- `ResolveWinner` remains a deprecated, non-pot-aware convenience.
- `cmd/` is still gitignored scratch space.

## Git and releases

`dev` is the integration branch, `master` is release-only. This overrides the global "branch from `origin/master`" default:
- Branch from `origin/dev` and PR into `dev`; back-merge `master` into `dev` when needed.
- Release: PR `dev` → `master`, tag `vX.Y.Z-alpha` on the merge commit, and bump `README.md` "Current version" in that same PR.
- The current released tag is `v0.8.0-alpha`. Bump `README.md` "Current version" in the release PR.
